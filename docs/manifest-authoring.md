# Manifest authoring

Tool manifests are embedded YAML files under `internal/catalog/data/tools/`. The canonical JSON Schema is `internal/catalog/schema/tool.schema.json`; runtime validation is stricter and is performed by `internal/domain/tool.Manifest.Validate` and `internal/catalog.Load`.

Every manifest needs schema version 1, a stable lowercase ID, a dotted lowercase category, a human-readable description, a version channel, and `upgrade_policy: never_automatically`. Executable names must be plain command names. Version arguments are passed directly to the executable, without a shell, and command/evaluation flags are rejected. Every platform architecture and installer mapping must be explicit.

Installer data is typed. Package-manager entries specify a manager, exact package ID, scope, and source label. Registry entries specify a supported ecosystem, exact package ID and version, and registry URL. Direct artifacts specify the publisher URL, catalog-pinned SHA-256, supported format, root directory, and any required limits, redirect hosts, version marker, PATH entries, typed setup action, or user-facing installation disclosure. Optional regional URLs must use the same pinned payload digest. Local archives, custom HTTPS URLs, and signed offline bundles are accepted only when their payload matches the embedded catalog data.

Manifests must not contain arbitrary install commands, arbitrary scripts, shell snippets, or user-specific repository configuration. A vendor setup step must use an explicitly enumerated typed action implemented by the client. Verify publisher URLs, SHA-256 values, package IDs, registry package versions, installer scope, and platform metadata against maintained source data before adding them. Never invent hashes or broaden platform support to make a manifest validate.

Tool dependencies and conflicts use catalog IDs and are checked for unknown references and dependency cycles. Put prerequisites shared by every operating system in `dependencies`; use `platform_dependencies` for prerequisites required only on declared operating systems. Every platform-specific dependency must support each declared architecture for that operating system. Profile IDs must reference existing tools. YAML fields not declared by the Go model are rejected. Run `go run ./cmd/catalog-check`, `go test ./...`, and `go vet ./...` after catalog or validation changes.
